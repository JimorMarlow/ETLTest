## Оптимиация для ESP8266

Реализацию для ESP32 не изменять - там все работает нормально.

Для ESP8266 сделать следующее (после возврата к начальному состоянию)

- Добавить логирование используемой кучи, как было сделано:
```
[LightControl] Init (ESP8266, no shared_ptr)...
[LightControl] Free heap before: <число>   ← должно быть > 1500
[LightControl] Settings loaded
[LightControl] AP started
[LightControl] Free heap after AP: <число> ← должно быть > 1500
[LightControl] Free heap after server: <число> ← должно быть > 500 (минимум!)
[LightControl] Server started (ESP8266)
```
- Оптимизировать код сервера контента для использования меньшей памяти
    - src\light_webui_html.h - все что можно перенести в PROGMEM (посмотри, как это было сделано "v0.3.2 — перенос HTML/SVG в PROGMEM") - обработчики не меняй, только сначала попробуем сократить затраты RAM. Оставь все умные указатели и обработчки как в ESP32. Попробуем сначала с ними.
    - Оставить только одну копию SVG иконки LIGHT_DEVICE_ICON_SVG, убрать дублирующееся из LIGHT_WEBUI_HTML
    - Сервер контента не будет менять никакие настройки, он будет только считывать текущие значения 
        etl::optional<etl::webui::server_config_t> load_wifi_config();
        etl::optional<etl::webui::ui_config_t> load_ui_config();
        убрать все, что связано с telegram и mqtt из light_webui, когда все заработает будем возвращать
