## Цель

Создать менеджер для работы с MQTT брокером: подключение, подписка/публикация, обработка разрывов. Менеджер работает поверх WiFi менеджера и зависит от его статуса.

## Контекст

Для интеграции устройств на базе ESP8266 и ESP32 нужен инструмент общения по MQTT протоколу. Используется библиотека `PubSubClient` для обеих платформ (единый код). Первая реализация без TLS/SSL.

### Архитектура

- **Общий механизм** работы с MQTT хранится в `lib/ETLTest/etl_mqtt.h/cpp` — базовый менеджер `etl::mqtt::manager` с универсальной функциональностью (подключение, подписка, публикация, обработка разрывов)
- **Конкретная реализация** для управления светом находится в `src/light_mqtt.*` — интеграция с брокером wqtt.ru, привязка к топикам и связь с `light_control::data::app()`

- [ ] **Этап 2: Проектирование интерфейса `etl::mqtt::manager`**
  - Конфигурация подключения (хранить в структуре):
    - `broker_host[64]` - адрес брокера
    - `broker_port` - порт (по умолчанию 1883)
    - `username[32]` - имя пользователя (опционально)
    - `password[64]` - пароль (опционально)
    - `client_id[32]` - идентификатор клиента
    - `enabled` - флаг включения MQTT
  - Публичные методы:
    - `begin()` - инициализация, загрузка настроек
    - `tick()` - неблокирующий цикл (поддержание связи, обработка сообщений)
    - `stop()` - отключение от брокера
    - `connect()` - подключение к брокеру
    - `disconnect()` - отключение от брокера
    - `publish(topic, payload, retain)` - публикация сообщения
    - `subscribe(topic, qos)` - подписка на топик
    - `unsubscribe(topic)` - отписка от топика
    - `is_connected()` - статус подключения
    - `set_message_callback(callback)` - колбэк на входящие сообщения
    - `set_status_callback(callback)` - колбэк на смену статуса
  - Наследование от `etl::settings::notify` для подписки на изменения MQTT конфига
  - Зависимость от `etl::wifi::manager` - проверка WiFi статуса перед подключением
  - Файлы: `lib/ETLTest/etl_mqtt.h`

- [ ] **Этап 3: Реализация подключения к брокеру**
  - Создать экземпляр `PubSubClient` с `WiFiClient`
  - Асинхронное подключение с таймаутами (не блокировать `tick()`)
  - Настройка LWT (Last Will Testament):
    - Топик статуса (например, `<client_id>/status`)
    - Сообщение `offline` публикуется брокером при обрыве
  - Публикация `online` при успешном подключении
  - Автоматическая переподписка на топики после восстановления связи
  - Файлы: `lib/ETLTest/etl_mqtt.cpp`

- [ ] **Этап 4: Обработка разрывов соединения**
  - В `tick()` мониторить `client.connected()`
  - При разрыве - автоматическое переподключение с задержкой

    - При потере WiFi - приостановка попыток подключения к брокеру
    - При восстановлении WiFi - автоматический MQTT reconnect
  - Событийная модель для уведомлений о статусе (callback подписчикам)
  - При отсутствии связи с брокером - контроллер работает автономно, без эмуляции

## Примечания

- **Архитектура:** общий механизм работы с MQTT хранится в `lib/ETLTest/etl_mqtt.h/cpp` (базовый менеджер), конкретная реализация для управления светом - в `src/light_mqtt.*` (интеграция с топіками wqtt.ru и `light_control::data::app()`)
- Использовать `PubSubClient` для обеих платформ (ESP8266/ESP32)
- Без TLS/SSL - чистый TCP на порт 1883
- Без эмуляции/буферизации при разрыве связи - контроллер работает автономно
- Пользователь может использовать web-интерфейс для управления при отсутствии MQTT
- Неблокирующая архитектура - вся работа через `tick()`
- **Критично:** При переключении серверов webui (content <-> settings) WiFi и mDNS останавливаются в `stop()` и запускаются заново в `begin()` - MQTT должен корректно обрабатывать это
- MQTT менеджер должен быть подписан на статус WiFi через `etl::wifi::manager` и не пытаться подключиться при отсутствующем WiFi
- **Безопасность:** Файл `secret.h` с паролями НЕ должен попадать в репозиторий - использовать `.gitignore` и шаблон `secret.h.example`
